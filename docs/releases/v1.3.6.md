# LocalChat v1.3.6

## 中文

### 更新亮点

- **大文件断点续传**：传输中断或失败后重试时，从接收端已收到的 4MB 分块处继续上传，不再整文件重传；接收端保留临时文件并在协商时回报进度，完成后仍做整体 SHA-256 校验。对旧版本设备自动回退为整文件重传。
- **更强的配对安全（pair_sas_v2）**：6 位配对校验码改为由双方设备密钥指纹确定性派生，两端各自本地计算并显示同一数字；接收方必须输入与对方屏幕一致的校验码才能允许配对。局域网内的中间人因持有不同密钥，无法让两端显示相同校验码，比对数字即可发现。旧版本设备自动回退原配对流程。
- **防重放加固**：修复加密信封与文件流鉴权的 nonce 先登记后验签问题，无效签名的请求不再占用防重放缓存，杜绝灌满缓存后重放有效消息的攻击路径。
- **工程化**：新增 GitHub Actions CI（格式校验 + 静态分析 + 全量测试），收紧 lint 规则，主界面与对话框源码按职责模块化拆分，Android 应用名显示修正为 LocalChat。

## English

### Highlights

- **Resumable large-file transfers**: after an interrupted or failed transfer, retrying resumes from the 4MB chunks the receiver already has instead of re-uploading the whole file; the receiver keeps the partial temp file, reports progress during negotiation, and the completed file still passes a full SHA-256 check. Peers on older versions automatically fall back to full re-transfer.
- **Stronger pairing security (pair_sas_v2)**: the 6-digit pairing code is now deterministically derived from both devices' key fingerprints, so each side computes and displays the same number locally; the receiver must enter the code shown on the other device before pairing is allowed. A man-in-the-middle on the LAN holds different keys and can never make both screens show the same code, so comparing the numbers exposes the attack. Older peers fall back to the previous pairing flow.
- **Anti-replay hardening**: fixed the nonce cache in message envelopes and file-stream authentication registering nonces before signature verification; requests with invalid signatures no longer consume anti-replay cache slots, closing the path of flooding the cache to replay captured messages.
- **Engineering**: added GitHub Actions CI (format checks + static analysis + full test suite), tightened lint rules, split the oversized UI and dialog sources into focused modules, and fixed the Android app label to display as LocalChat.
